# letool Starter Auto-Configuration Rules

## Rules

1. Auto configuration classes use `@AutoConfiguration`.
2. Feature switches use `@ConditionalOnProperty(prefix = "letool.<module>", name = "enabled", havingValue = "true", matchIfMissing = true)` only for lightweight internal runtime behavior; external, network, mail, or heavy adapter behavior must be explicit opt-in with `matchIfMissing = false` or the default.
3. Beans that users may replace must use `@ConditionalOnMissingBean` by type or by stable bean name.
4. Beans that depend on optional libraries must be guarded with `@ConditionalOnClass`.
5. Web-only modules must use `@ConditionalOnWebApplication`.
6. Servlet-specific classes must not load in non-web applications.
7. Real external Provider beans must be guarded by SDK classes and selected by explicit property.
8. Mock/stub providers must be explicit: prefer fail-fast for unsupported production providers; if a mock/stub is intentionally enabled, log a clear warning at startup and document the limitation.
9. Configuration properties classes must use `@ConfigurationProperties` and be registered by `@EnableConfigurationProperties`.
10. Auto configurations must have context runner tests for enabled, disabled, missing optional class, and user override paths where applicable.

| External providers | Several providers are mock/stub or extension-only. | Prefer fail-fast for unsupported production providers; pair intentional mocks with explicit docs and startup warnings. |
| Optional classpath | Some modules already use `@ConditionalOnClass`; coverage is uneven. | Fill matrix during P1/P2. |
